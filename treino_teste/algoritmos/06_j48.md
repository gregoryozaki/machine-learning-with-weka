# J48

## Funcionamento do algoritmo

O `J48` é um algoritmo de árvore de decisão. Ele cria regras de classificação a partir de divisões sucessivas nos atributos, usando limiares para atributos numéricos e categorias para atributos nominais.

Esse tipo de modelo é adequado para este problema porque as etapas de visualização mostraram separações por faixas em atributos como:

```bash
rack_power_density_kw
gpu_utilization_percent
water_usage_effectiveness
inlet_temperature_c
```

Além disso, o `J48` tem uma vantagem importante: o modelo gerado é interpretável, permitindo observar quais atributos aparecem nas principais decisões da árvore.

---

## Configuração no Weka

```bash
Scheme: weka.classifiers.trees.J48 -C 0.25 -M 2
Test mode: 10-fold cross-validation
Class: environmental_waste_risk_level
```

O parâmetro `-C 0.25` corresponde ao fator de confiança usado na poda da árvore. O parâmetro `-M 2` indica o número mínimo de instâncias por folha.

O algoritmo foi executado com validação cruzada estratificada de 10 folds, mantendo a mesma estratégia de avaliação usada para os demais modelos.

## Análise dos resultados

No `dataset_preprocessado.arff`, o `J48` obteve acurácia de **86,4985%**, Kappa de **0,7928** e F1 ponderado de **0,865**. Esse é um desempenho forte, bem acima dos baselines `ZeroR`, `OneR` e também acima de modelos mais simples como `NaiveBayes`.

A árvore gerada usou como primeiro critério de divisão o atributo:

```bash
rack_power_density_kw
```

Isso confirma uma evidência observada nas etapas anteriores: a densidade de potência do rack é um dos atributos mais relevantes para separar os níveis de risco de desperdício ambiental.

A árvore também utilizou outros atributos importantes, como:

```bash
water_usage_effectiveness
delta_t_c
gpu_utilization_percent
inlet_temperature_c
job_status
gpu_power_w
memory_utilization_percent
power_cap_w
```

Isso mostra que o modelo não dependeu de apenas uma variável, mas combinou atributos energéticos, térmicos, operacionais e ambientais.

A classe `alto` teve bom desempenho:

```bash
alto: 147 acertos de 158
recall alto: 0,930
```

Esse resultado é relevante porque a classe `alto` representa os casos mais críticos do problema. O modelo não classificou nenhum registro `alto` como `baixo`, o que é positivo do ponto de vista de risco ambiental.

O principal erro ocorreu entre `baixo` e `moderado`:

```bash
baixo -> moderado: 31 casos
moderado -> baixo: 37 casos
```

Também houve 12 registros `moderado` classificados como `alto`. Esse comportamento é aceitável e coerente com a análise visual, pois a classe `moderado` ocupa uma região intermediária e naturalmente se sobrepõe às classes vizinhas.

---

## Análise do dataset com AttributeSelection

No `dataset_preprocessado_attrselect.arff`, o `J48` obteve acurácia de **84,4214%**, Kappa de **0,7615** e F1 ponderado de **0,844**.

O desempenho geral caiu em relação ao dataset completo, mas a classe `alto` melhorou:

```bash
recall alto: 0,930 -> 0,956
```

A árvore com `AttributeSelection` ficou menor e mais simples:

```bash
Number of Leaves: 18
Size of the tree: 35
```

Enquanto no dataset completo a árvore tinha:

```bash
Number of Leaves: 48
Size of the tree: 88
```

Isso indica que a seleção de atributos simplificou o modelo. A árvore reduzida ficou mais interpretável, mas perdeu parte da informação complementar presente no dataset completo.

A classe `alto` foi muito bem identificada:

```bash
alto: 151 acertos de 158
```

O modelo também não classificou nenhum caso `alto` como `baixo`, o que novamente é positivo.

Por outro lado, houve piora na classe `baixo`:

```bash
recall baixo: 0,884 -> 0,795
```

A matriz de confusão mostra aumento de registros `baixo` classificados como `moderado`:

```bash
baixo -> moderado: 55 casos
```

Isso sugere que alguns atributos removidos pelo `AttributeSelection` ajudavam a diferenciar melhor `baixo` de `moderado`.

## Comparação entre os datasets

| Critério          | Dataset completo | Dataset com AttributeSelection |
| ----------------- | ---------------: | -----------------------------: |
| Acurácia          |         86,4985% |                       84,4214% |
| Kappa             |           0,7928 |                         0,7615 |
| F1 ponderado      |            0,865 |                          0,844 |
| Recall `baixo`    |            0,884 |                          0,795 |
| Recall `moderado` |            0,802 |                          0,827 |
| Recall `alto`     |            0,930 |                          0,956 |
| Tamanho da árvore |               88 |                             35 |
| Número de folhas  |               48 |                             18 |

O dataset completo teve melhor desempenho geral. A versão com `AttributeSelection` produziu uma árvore menor e melhorou o recall da classe `alto`, mas reduziu a acurácia geral e prejudicou a identificação da classe `baixo`.

Portanto, para o `J48`, o dataset completo é mais adequado quando o objetivo é equilíbrio geral entre as classes. A versão reduzida é interessante quando se deseja uma árvore mais simples e maior sensibilidade para a classe `alto`.

---

## Síntese

O `J48` apresentou desempenho forte e interpretável. O algoritmo confirmou a importância de atributos observados na análise visual, principalmente:

```bash
rack_power_density_kw
gpu_utilization_percent
water_usage_effectiveness
inlet_temperature_c
```

A melhor versão em desempenho geral foi:

```bash
dataset_preprocessado.arff
```

com:

```bash
Acurácia: 86,4985%
F1 ponderado: 0,865
Recall alto: 0,930
```

O dataset com `AttributeSelection` gerou uma árvore menor e aumentou o recall da classe `alto`, mas reduziu o desempenho geral.

Assim, o `J48` é um modelo forte para este trabalho, principalmente por combinar bom desempenho com interpretabilidade.
